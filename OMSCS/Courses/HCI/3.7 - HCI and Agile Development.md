# 3.7 - HCI and Agile Development

- Agile emphasizes early delivery, rapid experimentation
- So far we've discussed long prototyping feedback cycles
- There's no longer as much of a need to get software right the first time
- We still need the long process to get it right _at all_
- Rapid development helps build higher fidelity prototypes

![[Pasted image 20250529223930.png]]

## When to go Agile
- Low criticality (users are your testers)
- Frequently changing environments
- Small team that embraces change
- Low importance of documentation

![[Pasted image 20250529224225.png]]

## Prototyping
### Live Prototyping
Optimizely: drag/drop creation of real web pages
### A/B Testing
- rapid software testing between 2 software alternatives
- rapid testing small changes
- roll out B to a small number of users
- if B performs well, fully deploy B
- if B sucks, roll back B
### The Design Life Cycle
![[Pasted image 20250529225130.png]]

We simply go through this loop at warp speed.

## Mitigating Risk
- Start more traditional. Shift to Agile once things are up and running.
- Focus on small changes.
- Adopt a parallel track method.
- Be careful with consistency.
- Nest your design cycles.
