# 2.07 - Task Analysis

- try to restructure tasks to be more efficient using new interfaces
- 2 methods for task analysis
	- human information processor models
	- cognitive task analysis

## GOMS Model
- Goals
- Operators
- Methods
- Selection rules

Weakness
- doesn't address complexity
	- KLM-GOMS (keystroke-level model)
	- CMN-GOMS (Card, Moran, and Newell)
	- NGOMSL (Natural GOMS Language)
	- Other alternatives
		- Touch-level model (TLM)
		- Model Human Processor (MHP)
- assumes user is an expert. doesn't account for novices, errors.

Strength
- formalize user interaction
- predict efficiency of different methods

5 tips
- focus on small goals
- nest goals, not operators
- differentiate descriptive and prescriptive
- assign costs to operators
- Use GOMS to trim waste (assign costs to operators)

## Cognitive Task Analysis
> concerned with the underlying thought process associated with performing a task.

> Specifically, what we can't see.

1. Collecting preliminary knowledge.
2. Identify knowledge representations.
3. Apply focused knowledge elicitation methods.
	1. "Get users to tell us what's in their heads"
4. Analyze and verify data acquired.
5. Format results for intended application.

- Critical Decision Method (CDM)
- Task-Knowledge Structures (TKS)
- Cognitive Function Model (CFM)
- Applied CTA
- Skill-based CTA

Strengths
- emphasizes mental processes
- formal enough for interface design

Weaknesses
- time-sensitive
- may deemphasize context
- ill-suited for novices
