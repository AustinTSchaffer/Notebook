## Discoverability
- minimize user's memory load by making objects, actions, and options visible.
- Instructions for the use of the system should be visible or easily retrievable whenever appropriate.
- design should make all needed options and materials for a given task visible  without distracting the user.
- Discoverability is one of the challenges of gesture based interfaces.
- Tension between Discoverability and Simplicity

## Simplicity
- Tension between Discoverability and Simplicity
- Dialogues should not contain information which is irrelevant or rarely needed.
- The design should make simple, common tasks easy.
- Use of the design is easy to understand regardless of the user's experience, knowledge, language skills, or current concentration level.

## Affordances
- design interfaces that tell you how to use them
- familiarity principle
	- handles are pulled
	- knobs are turned
	- buttons are pushed
- relationship between the properties of an object and the capabilities of the agent that determine just how the object could be possibly used
- the presence of an affordance is jointly determined by the qualities of the object and the abilities of the agent that is interacting
- signifiers = in-context instructions
	- button labeled "menu"
	- arrows to indicate swipe direction
- affordance = inherent properties of the device
- perceived affordance
	- "pushability"
	- can be inaccurate (in-conflict with actual affordance)
- signifier = anything that helps reconcile affordance and perceived affordance
	- we can add signifiers
	- we can't add affordances

## Mapping
- mapping is a technical term - the relationship between the elements of two sets of things
- the system should speak the users' language, with words, phrases, and concepts familiar to the user
- Follow real world conventions, making information appear in a natural and logical order
- creating interfaces where the effect of using them is clear
- example
	- light switch
		- clear affordance
		- no mapping (what does this switch even do?)
	- knobs that indicate which burners on a stove they map to

## Perceptibility
- the system should keep users informed about what is going on through appropriate feedback within reasonable time
- the design communicates necessary information effectively to the user, regardless of ambient conditions or the user's sensory abilities
- feedback must be immediate
- feedback must also be informative
- poor feedback can be worse than none at all
- ceiling fan
	- one cord controls light
	- one cord controls fan
	- neither cord indicates the current setting of the ceiling fan
	- neither cord does anything unless the switch is turned on

## Consistency
- consistency in design is virtuous, it means that lessons learning with one system transfer readily to others
- users should not have to wonder whether different words, situations, or actions mean the same thing
- follow platform conventions
- the reuse principle
	- reuse internal and external components and behaviors
	- maintain consistency with purpose rather than merely arbitrary consistency
	- reduce the need for users to rethink and remember
- consistency/convention > first principles

## Flexibility
- accelerators (hot keys) may often speed up the interaction for the expert user such that the system can cater to both inexperienced and experienced users
- the design accommodates a wide range of individual preferences and abilities
- appears to clash with equity

## Equity
- the design is useful and marketable to people with diverse abilities
- provide the same means for use for all users
- avoid segregating or stigmatizing any users
- experience should be the same across all users
- "security is part of the user experience"
	- password constraints are a tool to make sure novices get the same level of security as expert users
## Ease / Comfort
- the design can be used efficiently and comfortably and with a minimum of fatigue
- appropriate size and space is provided for approach, reach, manipulation, and use regardless of user's body size, posture, and mobility

## Structure
- design should organize the user interface purposefully
- related things should be together
- unrelated things should be apart
- differentiate dissimilar things
- similar things should resemble each other

## Constraints
- account for user error
- user cannot make errors. The system should be designed to allow users to recover from errors.
- Constraints are powerful clues, limiting the set of possible actions
- the use of constraints in design lets people readily determine the proper course of action, even in a novel situation
- even better than good error messages is a careful design which prevents a problem from occurring in the first place
- eliminate error-prone conditions or check for them and present users with a confirmation option before the commit to the action
- "Prevent the user from putting in input that wasn't going to work anyway"
- 4 sub-categories
	- Physical constraints (3-prong plug, USB sticks)
	- Cultural constraints
	- Semantic constraints (similar to affordances)
	- Logical constraints (self-evident based on situation at hand)

## Tolerance
- user can't cause too much trouble accidentally
- support undo and redo
- design should be flexible and tolerant
- mistakes should be recoverable
- users should be able to experiment (enhances discoverability)
- minimize hazards (principle of recoverability)
- "A computer should not harm your work or through inactivity allow your work to come into harm."

## Feedback
- refer back to "Perceptibility"
- error messages should be expressed in plain language (no codes) precisely to indicate the problem and constructively suggest a solution.
- design should keep users informed of actions or interpretations, changes of state or conditions, and errors.

## Documentation
- try to avoid the need for documentation altogether
- "The system should be self-documenting, and the system should also be documented."
- Information should be easy to search, and not be too large.
- Should be framed in terms of tasks.
- Older docs just lists out what the interface can do.
