## Metaphors and Analogies
- There are positive and negatives in analogies in design
- Analogies make the interface more learnable, but may restrict the interface to outdated constraints
- whenever possible
	- leverage analogies to the real world
	- leverage principles from past interfaces
	- this will help the user learn the interface as quickly as they can
- challenge
	- Why are we designing technology if we're not providing users anything new?
	- We want to enable people to do things they've never done before
	- How do we teach people that they don't have to adjust their temperature anymore?

## User Error - Slips and Mistakes
- "There's no such thing as user error."
- User error comes from poor interface design.

![[Pasted image 20250520223437.png]]

**types of slips**
- action-based slips
	- click the wrong button
	- performed right action on wrong object
- memory lapse = forget something they need to do

**types of mistakes**
- rule-based = right model of reality, wrong action chosen
- knowledge-based = wrong model of reality, wrong action chosen as a result
- memory lapse = forgetting to fully execute a plan

> leverage the tolerance principle to make sure slips and mistakes aren't catastrophic

## Learned Helplessness
- principle of feedback = user learns from the output on what they should have input
- no discernable output from a given input
- learned helplessness
	- user learns that they are helpless to accomplish their goal in a given interface
	- no matter what I do, I'm doomed to failure
	- there appears to be no mapping from input to the correct output 

## Expert Blind Spot
- when you're an expert, there's parts of the context that you do subconsciously
- you need to teach the user how to use what you've designed, without being able to speak to them directly, using only the interface itself (and without overwhelming them with instructions)
- need to assume the user is not an expert
- "I am not my user."
