# 3.6 - Evaluation

- Get frequent feedback from the users
- methods for evaluation
	- qualitative
		- usable?
		- intuitive?
	- quantitative / empirical
		- user uses it faster?
		- sales increased?
	- predictive evaluation
		- evaluation without users
		- not our favorite
		- cheaper and faster than getting test subjects
- 5 tips
	- efficiency
		- how long does it take users to do specific tasks?
		- narrow scope
		- tailored to experts
	- accuracy
		- how many errors does a user commit while executing a task?
		- narrow scope
		- tailored to experts
	- learnability
		- can they achieve competency?
	- memorability
		- do they retain competency?
	- satisfaction
		- did they like it?
		- cognitive load
		- did they download the app after the session was over?

## Terminology
- Reliability = whether a measure is consistent
- Validity = how accurate an assessment reflects reality
- Generalizability = Can lessons learned in evaluation be applied to the broader population?
- Precision = a measure of how specific a measure is

## Qualitative Evaluation
- What did you like? Dislike?
- What were you _thinking_?
- interviews
- think aloud
- focus groups
- surveys
- etc
### Designing a Qualitative Evaluation
- is this based on prior experience or is it a live demonstration?
- is it synchronous or asynchronous?
- is there one interface or are there multiple prototypes?
	- make sure to vary the order between test subjects
- think aloud protocol or post-event protocol?
	- pros and cons to each
	- use a mix of the 2
	- use TAP early and PEP later
- feedback from individuals or groups?
	- groups can lead to better explanations
	- groups can also lead to the same issues as in [[3.4 - Design Alternatives]]
- 5 tips
	- run pilot studies
	- focus on feedback (don't explain rationale)
	- use questions to lead users when they get stuck
	- instruct users what to do, not how (focus on task)
	- capture satisfaction

## Empirical Evaluation
- Goal: Strong conclusions
- most empirical evaluations are comparisons
- is there a measurable difference between these designs?
- treatments
	- multiple configurations of the software
	- measure how they are different
	- try to change only one variable
- within-subjects experiment
	- each subject receives both treatments
	- make sure the users receive treatments in a different order
- randomly assign users to groups (not accidentally based on order/gender/height/weight/punctuality/etc)
- we need to do STATS
	- hypothesis testing
	- null hypothesis
	- statistical significance

### Quantitative Data and Empirical Tests
![[Pasted image 20250522231240.png]]

The hard part is determining what kind of data you have. Once you identify that, it should be easy to lookup the type of statistical test you need to use and plug in the data.
#### Summary

![[Pasted image 20250522233108.png]]

5 tips
- control what you can, document what you can't
- limit your variables (curse of dimensionality)
- work backwards when designing your experiment
- script your analyses in advance. You can always find conclusions if you torture the data enough.
- Pay attention to power.
	- Detecting big effects requires few samples.
	- Detecting small effects requires many samples.

#### Nominal

![[Pasted image 20250522231439.png]]

- IV: Category
- DV: Distribution among categories
- $H_{null}$: distributions are equal
- $H_{alternative}$: distributions are unequal
- Recommended tests
	- Chi-squared test
	- (Alt) Fisher's exact test
	- (Alt) G-test
#### Ordinal

![[Pasted image 20250522231446.png]]

- IV: Category
- DV: Distribution among ranked categories
- $H_{null}$: distributions are equal
- $H_{alternative}$: distributions are unequal
- Recommended tests
	- Kolmogorov-Smirnov test
	- (Alt) Chi-squared test
	- (Alt) Median test
#### Interval / Ratio

![[Pasted image 20250522231633.png]]

- IV: Category
- DV: Average of outcomes
- $H_{null}$: outcomes are equal
- $H_{alternative}$: outcomes are unequal
- Recommended tests
	- Student's t-test (if distributions are normal)
	- (Alt) MWW test
	- (Alt) Kruskal-Wallis test
#### Ordinal / Nominal (3+ treatments)

![[Pasted image 20250522231845.png]]

- Type I Error
	- "False Positive"
	- False rejection of null hypothesis
- Type II Error
	- "False Negative"
	- False retention of null hypothesis
- IV: Category
- DV: Distribution among categories
- $H_{null}$: all distributions are equal
- $H_{alternative}$: any one distribution is unequal
- Recommended tests
	- Chi-squared test
	- (Alt) Fisher's exact test
	- (Alt) G-test
- First check for $H_{alternative}$ to see if any one distribution is unequal, only then do we perform more tests to determine which distribution(s) is/are unequal.
#### Interval / Ratio (3+ rreatments)

![[Pasted image 20250522232233.png]]

- IV: Category
- DV: Average of outcomes
- $H_{null}$: all outcomes are equal
- $H_{alternative}$: any one outcome is unequal
- Recommended tests
	- Analysis of Variance (ANOVA)
	- (Alt) Kruskal-Wallis test
	- (Alt) Median test
- If ANOVA rejects the null hypothesis, follow up with pairwise t-tests
#### Interval / Ratio (Non-Categorical)

![[Pasted image 20250522232513.png]]

- IV: Interval/Ratio Data
- DV: Interval/Ratio Data
- $H_{null}$: Variables are unrelated
- $H_{alternative}$: Variables are related
- Recommended tests
	- Linear Regression
	- (Alt) Logistic Regression, etc.
#### Binomial

![[Pasted image 20250522232738.png]]

- "trials have only 2 possible outcomes"
- t-tests require a standard deviation
- IV: Category
- DV: Binomial Data
- $H_{null}$: Proportions are equal
- $H_{alternative}$: Proportions are unequal
- Recommended tests
	- 2-sample binomial test
	- (Alt) 1-sample binomial test
