# 2.01 - Introduction to Principles

> established principles that we've uncovered after decades of designing computer interfaces

- focusing on the tasks
- role of interfaces
- role of the user
- user experience at multiple levels

- interfaces
	- pencils to write
	- steering wheel to drive
	- to design a good interface, we must understand the user, and the task they're trying to solve, their goals, etc
- tips for identifying tasks
	- watch real users
	- talk to the users
	- start small (smallest units of actions)
	- abstract up (what? why? what? why? what? why?)
	- you are not your user
- usefulness and usability
	- useful - a paper map
	- usability - GNSS-enabled pathfinding applications
	- usable = useful + lower cognitive load

## Views of the User

What is the user?
- processor
	- takes input
	- produces output
	- interface must fit within human limits
	- evaluated by quantitative experiments
	- behaviorist/behaviorism view of psychology
		- Watson
		- Pavlov - classical conditioning
		- Skinner - operant conditioning
	- What designs result in desirable behaviors? Don't care much about why.
- predictor
	- want the user to predict what will happen in the world
	- interface must fit with the user's knowledge
	- evaluated by qualitative studies
	- Ex situ studies: in a controlled or otherwise inauthentic environment
	- still focusing on one-user-one-task
	- Cognitivism
		- Immanuel Kant
		- Rene Descartes
		- Is knowledge inborn, or developed solely by experience?
		- Notable pioneers: Chomsky, Carey, McCarthy, Minsky, Newell, Simon
- participant
	- interface must fit with the context
	- evaluated by in situ studies
	- in situ: in an authentic environment
	- Functionalism, Systems
		- Hutchins
		- Suchman
		- Salomon
		- Nardi

## Designing with the Three Views
- processor model
	- experiment setup
		- prep a few different users
		- time users using each interface
		- pick the interface which was most efficient
	- pros
		- may use existing data
		- enables objective comparisons
	- cons
		- doesn't find reason for differences
		- can't differentiate by expertise
		- helps optimize, not redesign
- predictor model
	- interviews, focus groups, prototypes
	- is this icon misleading?
	- voice interface? text interface? depends on context
	- pros
		- more complete picture of the interaction
		- targets different levels of expertise
	- cons
		- analysis may be expensive
		- analysis is subject to biases
		- ignores broader interaction context
- participant
	- interface and user in the context in which they actually interact
	- pros
		- evaluates interaction in context
		- captures authentic user attention
	- cons
		- expensive to perform and analyze
		- requires real, functional interfaces, and fully functional automations that the interfaces control
		- subject to uncontrollable variables

- each model is useful in specific contexts
	- participant view: holistic
	- predictor view: focused
	- processor view: optimization

## User Experience

- phenomenon that emerges as a result of the user interacting with a task through an interface
- attempt to design that experience
- do they feel the interface was designed for them?
- are the users properly represented in the system?

## Designing for Morgan
- processor: what is communicated, when, and how?
- predictor: how the interfaces mesh with Morgan's immediate needs?
- participant: how the interface interacts with Morgan's life as a whole?
