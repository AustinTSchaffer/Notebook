# 06.4 - NP - CNF and SAT Supplement
This document aims to give a quick overview of how CNFs work in this course, with specific attention on applicability to SAT problems in the NP section of the course. It is not required reading and the document's content is generalizable from the lectures and book. This document addresses common questions and errors that students run into in the NP section.

## Introduction
A boolean expression is an expression in Boolean logic, composed of Boolean **variables** and **operators**. It can be either true or false, but not both at the same time.

Examples
- $a$
- $a \vee b$
- $((a \rightarrow b) \wedge (\neg b \vee a \vee (\neg{b} \wedge a))) \rightarrow a \vee \neg b$
- $a \iff b \wedge c$

CNF refers to "Conjunctive Normal Form" for a boolean expression, CNF expressions look something like this:

- $(a) \wedge (b)$
- $(a \vee \neg b) \wedge (c \vee d) \wedge (\neg e \vee a)$
- $(a \vee b \vee c \vee d) \wedge (\neg a \vee \neg b \vee \neg c \vee \neg d)$

A boolean expression in CNF is composed of **clauses** connected to each other with AND operators ($\wedge$). Each clause is composed of **literals** connected to each other with OR operators ($\vee$). A CNF expression is a type of Boolean expression.

> There also exists "Disjunctive Normal Form", which are expressions composed of AND clauses connected by OR operators. This is not relevant, just a fun fact.

## Variable vs Literal
A Boolean variable is a variable in a boolean expression that can either be assigned the value of True of False. This is similar to how variables in an algebraic expression can be assigned a single, specific value.

Within the context of CNFs and our course, a literal is the smallest part of a boolean expression, and either is the value of a variable or the negation of that variable.

Consider the following example: $$(a \vee b \vee c \vee d) \wedge (\neg a \vee \neg b \vee \neg c \vee \neg d)$$
There are 4 variables ($a, b, c, d$) and 8 literals ($a, b, c, d, \neg a, \neg b, \neg c, \neg d$).

> **Important:** Variables get truth assignments, not clauses nor literals. Some problem statements limit the number of variables. Some problem statements limit the number of literals. These are important distinctions.

## Clauses
A CNF expression is made up of a number of clauses. By default, we defined $m$ to be the number of clauses for a particular CNF expression.

Unless otherwise specified, a clause can have
- one or more literals (with no max, but must be finite)
- both a literal and its opposite (such as $a$ and $\neg a$)

All literals within a clause must be connected using the OR operator. A clause may *not*
- have a "hard coded" value of true or false
- be empty (no literals)
- any other operators aside from OR
- any parens inside the clause (e.g. $(a \vee (b \vee c))$ is not allowed, though the parens are redundant in this example.)
- repeated instances of the same literal within the same clause.

Typically, repeated literals are allowed in the mathematical definition of a CNF, but allowing an arbitrary (but finite) repetition of literals greatly complicates the runtime analysis, because this means the size of a clause is no longer limited by the number of variables in the overall boolean expression. Simplification can also interfere with the formation of certain SAT-like problems. Therefore, for our class, we simply expect that CNFs as inputs to SAT-like problems do NOT contain repeated literals.

While these may be permitted in more general Boolean expressions, if a boolean expression has any of these features, it is no longer in CNF.

A CNF expression can contain one or more clauses. Multiple clauses are connected with AND operators. Clauses may not be negated, and no other operators are allowed.

## SAT-like Problems
Conventionally, $m$ represents the number of clauses, and $n$ represents the number of variables. Together, these form the input size for the overall CNF expression.

Runtimes for common operations:

- Checking whether a SAT assignment satisfies the original input: $O(nm)$
	- The expression has $m$ clauses
	- Each clause is of length $O(n)$ ($2n$ max length per clause)
	- In the worst case, every literal in every clause needs to be checked. This occurs when only the last literal in each clause in satisfied.
- Checking whether a clause is satisfied: $O(n)$
	- Iterate through all literals in a clause.
	- This can early-exit once the first satisfied literal is found, but it may be the last one, and there may be no satisfied literals in the clause.
- Adding a literal to a clause: $O(1)$
	- A clause can be modeled as a list, in which case this would be an append operation.
	- A clause can also be modeled as a bitmask of the literals it contains.
- Removing a clause from a CNF expression: $O(1)$
	- Once the appropriate clause is identified, we can remove it in constant time.
	- This implies the "bitmask" formulation of the previous point.
- Accessing truth assignment of a variable/literal: $O(1)$

## Useful Equivalent Expressions
If you have a boolean expression that you would like to convert into CNF, the following can be helpful tools.

- $\neg(\neg a)=a$
- $a \rightarrow b = \neg a \vee b$
- Demorgan's Law
	- $\neg(a \wedge b) = \neg a \vee \neg b$
	- $\neg(a \vee b)=\neg a \wedge \neg b$

## Common Mistakes
- Referring to an "assignment" for a clause or literals. Most SAT problems output an assignment to variables.
- Performing an input transformation that does not result in a valid CNF expression.
	- Hard-coding a truth value
	- Using invalid operations
- Conflating "variables" with "literals" when the problem statement explicitly limits one or the other.
- Conflating a clause containing a single literal with a literal/variable. This can make the overall explanation for the transformation or correctness of the reduction very difficult to interpret.
