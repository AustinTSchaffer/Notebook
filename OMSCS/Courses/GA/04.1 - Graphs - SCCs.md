## DFS: Paths
- DFS: connected components.
- How to find a path between connected vertices?

Using the DFS algorithms from earlier, we can use `prev[]` to iterate backwards from a given node to see if it was found while exploring from some other node.

How do we get connectivity info for directed G?
- Use DFS: add pre/postorder numbers.
- When you first explore a node, you set the preorder number and then increment the counter.
- When you finish exploring a node, you set the preorder number and then increment the counter.

## Types of Edges
![[Pasted image 20260227124812.png]]

For a given DFS tree, with pre/postorder numbers, and  For a given edge $e=(a,b)$, the edge can have one of the following types.

- tree-edge
	- B->A, A->D
	- pre(a) < pre(b)
	- post(a) > post(b)
- back edge
	- E->A, F->B
	- pre(a) > pre(b)
	- post(a) < post(b)
- forward
	- D->G, B->E
	- pre(a) < pre(b)
	- post(a) > post(b)
- cross
	- F->H, H->G
	- pre(a) > post(a)
	- post(a) > post(a)
	- There's no situation where the back edge goes the other way. If there's a cross edge pointing the other direction, DFS should have explored that edge and it would actually be a tree-edge.

For back-edges, the post order number goes up. For all other edge types, the post-order number goes down.

## Cycles
G has a cycle iff its DFS tree has a back edge.

## Topological Sorting
- DAG = directed acyclic graph
- no cycles = no back edges
- Topologically sorting a DAG = order vertices so that all edges go lower to higher
- Run DFS on DAG G
	- For all z->w, we know post(z) > post(w)
	- order vertices by descending postorder number
	- Create array of length 2n. Insert vertices into the array based on their postorder number. Walk backward through the array to construct the toposort array.


$O(n+m)$

## DAG Structure
![[Pasted image 20260227130341.png]]

- All DAGs have at least one valid topological ordering. Some DAGs have more than one.
- All DAGs have at least one source vertex
	- a source vertex has no incoming edges
	- the first vertex in topological order has no incoming edges
- All DAGs have at least one sink vertex
	- a sink vertex has no outgoing edges
	- the last vertex in topological order has no outgoing edges

**Alternative topological sorting algorithm**
- until the graph is empty
	- Find a sink
	- output it to toposort array
	- delete it from the graph

## Connectivity in Directed Graphs
- vertices $v$ and $w$ are **strongly connected** if
	- there is a path $v$ to $w$
	- there is a path $w$ to $v$
- SCC = strongly connected component
	- maximal set of strongly connected vertices.
- Metagraph
	- contains a vertex for each SCC
	- each metavertex encapsulates 1 or many vertices from source graph
	- metaedges connect metavertices if at least one vertex in one SCC connects to at least one vertex in the other SCC
	- Always a DAG

## SCC Algorithm
- Find sink SCC S, output it, remove it, repeat
- Why sink SCC?
	- They're easier to find.
	- Take any v in S where S is a sink SCC
	- Running explore(v) visits all of S and nothing else.
- In a DAG, the vertex with the **lowest** postorder number is a **sink**
- In a general directed G, does v with lowest postorder number always lie in a sink SCC? (No.)

![[Pasted image 20260227132259.png]]

- In a DAG, the vertex with the **highest** postorder number is a **source**
- In a general directed G, does the v with the highest postorder number always lie in a source SCC? (**YES.**)
- We can find sinks in $G=(V,E)$ by reversing $G$, making $G^R=(V,E^R)$
- If a pair of vertices are strongly connected in $G$, then they are also strongly connected in $G^R$
- If an SCC is a source SCC in $G_{SCC}$, then it's a sink SCC in $G^R_{SCC}$.
- Running DFS on $G^R$ and taking the vertex with the highest postorder number finds a vertex in a source SCC in $G^R_{SCC}$, which is a sink SCC in $G_{SCC}$.
- We then create an array of the vertices of $G$, sorted by descending order of their postorder numbers from the DFS on $G^R$. We then take the left-most vertex of that array and run DFS from it, finding all of the vertices which are in the SCC of the sink SCC that contains that vertex. As we explore them, we remove those vertices from the array. We continue in this fashion, building the SCCs of $G$.
- As we continue to find more sinks, we can produce $E_{SCC}$ based on whether we find an edge from the current sink SCC to a previously found SCC.
