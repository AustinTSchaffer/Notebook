# 02.1 - Dynamic Programming 2 - Knapsack
> Knapsack Problem

## Knapsack Problem
- **Inputs:**
	- $n$ objects $O=\{1,...,n\}$
		- Integer weights: $W=\{w_1,...,w_n\}$
		- Integer values: $V=\{v_1,...,v_n\}$
	- Total capacity $B$
- **Goal:** find subset $S$ of $O$ that maximizes the expression:
$$\sum_{i \in S}v_i:\left(\sum_{i \in S}w_i \le B\right)$$
- It's the "raiding a dungeon in a Bethesda game" algorithm, except we can't just limp home over-encumbered.

### Variants
1. One copy of each object - no repetition.
2. Unlimited supply of each object - with repetition.

## Knapsack with No Repetition
### Greedy Algorithm Example
| object | value | weight | v/w           |
| ------ | ----- | ------ | ------------- |
| 1      | 15    | 15     | 1             |
| 2      | 10    | 12     | $\frac{5}{6}$ |
| 3      | 8     | 10     | $\frac{4}{5}$ |
| 4      | 1     | 5      | $\frac{1}{5}$ |
- $B=22$
- Version: one copy
- Optimal Solution:
	- $S=\{2, 3\}$
	- $\sum_{i \in S}v_i=18$
	- $\sum_{i \in S}w_i=22$
- The greedy approach sorts objects by their value-to-weight ratio: $r_i=\frac{v_i}{w_i}$, and then pulls objects from that queue until the queue is empty or $\sum_{i \in S}w_i=B$. In this example, the greedy approach grabs objects 1 and 4.
- Greedy Solution:
	- $S=\{1,4\}$
	- $\sum_{i \in S}v_i=16$
	- $\sum_{i \in S}w_i=20$

### DP Design - Attempt 1
- **Step 1:** Define subproblem
	- $K(i)$ = max value achievable using a subset of the first $i$ objects: $\{o_1,...,o_i\}$.

- The key is that the suboptimal solution to $K(2)$ leaves available capacity for object 3.
- We want to take the optimal solution which maximizes the available capacity.
- The subproblem definition is not adequate, because $K(3)$ does not build on $K(1)$ and $K(2)$, and settles into a suboptimal solution.

### DP Design - Attempt 2
#### Subproblem
- We will have 2 parameters
	- $i=$ the prefix of objects we're considering
	- $b=$ the remaining available weight
- For $0 \le i \le n$ and $0 \le b \le B$:
	- Let $K(i,b)=$ the max value achievable using a subset of objects $\{1,...,i\}$ and total weight $\le b$.
- Our goal is to compute $K(n,B)$
#### Recurrence
- if $w_i \le b$
	- then $K(i,b)=max\{v_i+K(i-1,b-w_i), K(i-1,b)\}$
	- else $K(i,b)=K(i-1,b)$
- Base cases
	- No objects remaining, nothing to put in the backpack. $K(0,b)=0$
	- No weight available, no space for objects. $K(i,0)=0$

#### Pseudocode
$KnapsackNoRepeat(W_{1..n}, V_{1..n}, B)$
    $\text{for } b=0 \rightarrow B: K(0,b) = 0$
    $\text{for } i=0 \rightarrow n: K(i,0) = 0$
    $\text{for } i=1 \rightarrow n:$
        $\text{for } b=1 \rightarrow B:$
            $\text{if } w_i \le b$
	            $\text{then } K(i,b)=max\space\{v_i+K(i-1,\space b-w_i),\space K(i-1,b)\}$
		        $\text{else } K(i,b)=K(i-1,b)$
	$\text{return }(K(n,B))$

Runtime complexity:
- Total: $O(n*B)$
	- $O(B)$
	- $O(n)$
	- $O(n)$
		- $O(B)$
			- $O(1)$
	- $O(1)$

Space Complexity: $O(n * B)$

The running time is **NOT** polynomial in the input size. To represent the number $B$ takes $O(log_2B)$ space. That essentially means this algorithm has exponential time complexity. Therefore our goal should be to find a running time which is polynomial in $(n, log_2B)$.

**Knapsack is an NP-Complete problem.** If we design a polynomial-time algorithm for Knapsack, that would then mean there exists a polynomial-time algorithm for all NP-Complete problems.

## Knapsack with Repetition
> Unlimited supply: We can use an object as many times as we'd like.

$K(i,b)$ = max value attainable from a multiset of objects $\{1,...,i\}$ with weight $\le b$

In the other version of this problem (without repetition), we either
1. include a copy of object $i$, symbolized by the expression: $K(i-1,b-w_i)+v_i$
2. don't include a copy of object $i$, symbolized: $K(i-1,b)$

In this version, we either
1. include no more copies of object $i$, symbolized: $K(i-1,b)$
2. include another copy of object $i$, symbolized: $K(i, b-w_i)$

We don't decrement $i$ in the 2nd case, because we might use yet another copy of object $i$. Taking the max of these 2 recursive expressions results in an appropriate recurrence relation. $K(i,b)=max\{K(i-1,b),\space v_i+K(i,b-w_i)\}$

While building the DP table, the recurrence relation takes the max of either (a) the value in the same column but previous row, or (b) a value from earlier in the current row. This is almost the same pseudocode as [[02.1 - Dynamic Programming 2 - Knapsack#Pseudocode]], and the same runtime complexity $O(n\cdot B)$ and space complexity $O(n \cdot B)$.

### Can we Simplify?
Why did we have the parameter $i$? It keeps track of which objects we've already consdidered. In this version, we're allowed to use an object multiple times. We can in fact get rid of it.

In this version, we only have a single parameter for the weight available $b$.

#### Subproblem
for $b$ where $0 \le b \le B$, $K(b)$ = max value attainable using weight $\le b$.

#### Recurrence
$$K(b)=\max_i\{v_i+K(b-w_i) : 1 \le i \le n \text{ and } w_i \le b\}$$
#### Pseudocode
$KnapsackRepeat(W=\{w_1,...,w_n\}, V=\{v_1,...,v_n\},B):$
    $\text{for } b=0 \rightarrow B$
		$K(b)=0$
		$\text{for } i=1 \rightarrow n$
		$\text{if } w_i \le b \text{ and } K(b) \le (v_i + K(b-w_i))$
			$\text{then } K(b)=v_i+K(b-w_i)$
$Return(K(B))$

- Time complexity: $O(n\cdot B)$
- Space complexity: $O(n)$

#### Output the Multiset?
We can add another table $S$ with size $B$, which keeps track of the previous item selected for each discovered $b$. This enables backtracking while prepping the output.
