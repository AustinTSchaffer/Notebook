# 2.22 k-th Smallest of 2 Sorted Arrays
![[Pasted image 20260207172241.png]]
## Relevant
[[03.2 - Divide and Conquer 2 - Linear-Time Median]]
## Algorithm Attempt 1
- The arrays are sorted, so we can merge them in $O(m+n)$ time.
- We can then access the $k$-th element of the merged array in O(n) time.
- This is an $O(m+n)$ algorithm.

## Algorithm Attempt 2
- We can concatenate the 2 lists in $O(1)$ time
- We can then apply the $select$ algorithm to the combined (now unsorted) list. This algorithm runs in $O(n)$ time for an array of size $n$. For this array, the algorithm runs in $O(n+m)$ time.

## Notes
- Let's refer to the sorted lists as list A and list B
- If we take the kth smallest in list A, then the smallest in B, and the smallest of B is more than the kth smallest in A, then the answer is just the kth smallest in A.
- The opposite is true as well.
- We can also check the smallest in A against the largest in B. If the largest in B is smaller than the smallest in A, then we just take the kth smallest of B.
- The issue really lies in the ranges of A and B overlapping in ranges $A[1..k]$ and $B[1..k]$

### General Process

- $|A1|=n$
- $|A2|=m$
- Special Case handling
	- $k \lt n+m$
	- $n>0$
	- $m>0$

In the special cases where $k=n+m$, or $n=0$, or $m=0$, the problem is trivialized. Those can be handled up front.


For $0 \le i \le k$...
- We need to be careful about our definitions of $f_1$ and $f_2$ in order to make sure we're grabbing enough elements from $A1$ and $A2$.
- If $k>m$, then at each iteration, we need to take at least $k-m$ elements from $A1$.
- Conversely, if $k>n$, then at each iteration, we need to take at least $k-n$ elements from $A2$.
- We already know that $k \lt n+m$, which simplifies the edge case handling a little bit. 
- We can redefine $i$ using this information...

For $(max \space \{0,k-m\}) \le i \le (min\space\{k, n\})$
1. Consider the first $f_1=i$ elements from $A1$ and the first $f_2=k-f_1$ elements from $A2$. These define ordered slices of $A1$ and $A2$, which includes some of the smallest values of $A1|A2$.
	- If $f_1=0$, then we're taking $0$ elements from $A1$ and $k$ elements from $A2$. This happens on the first iteration.
	- If $f_2=0$, then we're taking $k$ elements from $A1$ and 0 elements from $A2$. This happens on the last iteration.
2. Compare the 2 slices against what remains untaken from $A1$ and $A2$.
	- For convenience, we define out of bounds handling within our mathematical notation.
		- $A_x[c]=null:c \le 0$
		- $A_x[|A_x|+c]=\text{null}:c>0$
		- $max \space \{null, v\}=v$ 
		- $min\space\{null,v\}=v$
		- In actual code, this is handled through explicit bounds checking.
	- If $max \space \{A1[f_1],A2[f_2]\}<min \space \{A1[f_1+1],A2[f_2+1]\}$
		- then
			- we've found the correct partitions of $A1$ and $A2$ for a given target $k$.
			- $return ( max \space \{A1[f_1],A2[f_2]\} )$
			- If we're using the "median of an even sized dataset is the average value between the 2 actual medians" handling, we can  $return (\frac{max  \{A1[f_1],A2[f_2]\} +  min \{A1[f_1+1],A2[f_2+1]\}}{2})$
		- Otherwise
			- We know that $i$ is the wrong place split $A1$.

Visually, this is what we're doing:
![[Pasted image 20260213121456.png]]

Within each blue box, the top row of numbers represents $A1$ and the bottom row of numbers represents $A2$. The vertical white line represents the partitioning of $A1$ and $A2$.

In order to optimize this procedure, we have to find a better method for iterating over $(max \space \{0,k-m\}) \le i \le (min\space\{k, n\})$ in order to find the value of $i$ which correctly partitions $A1$ and $A2$. Given what we know about algorithms so far, the best option is likely a binary search over the range.

To start, the $max \space \{A1[f_1],A2[f_2]\}<min \space \{A1[f_1+1],A2[f_2+1]\}$ comparision has access to information that is being thrown away. The arrays are sorted, so we already know that $A1[f_1]<A1[f_1+1]$ and $A2[f_2]<A2[f_2+1]$.
- If $A1[f_1]>A2[f_2+1]$, then we need fewer elements from the head of $A1$ and more elements from the head of $A2$.
- If $A2[f_2]>A1[f_1+1]$, then we need fewer elements from the head of $A2$ and more elements from the head of $A1$.
- What about the case where $(A1[f_1]=A2[f_2+1]) \vee (A2[f_2]=A1[f_1+1])$?

### Binary Search
Let's review the visual example again. Ignore $n$ and $m$. Presume we're trying to find $k=5$ of two sorted arrays of infinite length.

![[Pasted image 20260213121456.png]]

The boxes are considering the first $i=4$, $i=3$, and $i=2$ elements of $A1$, respectively.
- Looking at $i=4$, how do we eliminate the possibility of the answer being $i \gt 4$?
	- We can see that $A1[4]>A2[2]$.
	- This means that taking the first 5+ elements of $A1$ will only show the same pattern.
	- We've put the partition of $A1$ too far to the right.
- Looking at $i=2$, how do we eliminate the possibility of the answer being $i \lt 2$?
	- We can see that $A2[3]>A1[3]$.
	- This means that taking the first 4+ elements of $A2$ will only show the same pattern.
	- We've put the partition of $A2$ too far to the right.

So now we've found the conditions for implementing a binary search.
- $low:=max \space \{0,k-m\}$
- $high:=min\space\{k, n\}$
- $f_1:=(high-low)//2$
- $f_2:=k-f_1$
- if $A1[f_1] \le A2[f_2+1]$
	- then if $A2[f_2] \le A1[f_1+1]$
		- then $Return(max\space\{A1[f_1],\space A2[f_2]\})$
		- otherwise $low:=mid$ (we need fewer elements from A2)
	- otherwise $high:=mid$ (we need fewer elements from A1)

## Algorithm
The objective is to find the $k$-th element of the combination of 2 sorted arrays. To perform this, we will take the first $i$ elements of $A1$ and the first $k-i$ elements of $A2$. This partitions both A1 and A2 into 2 pieces each, such that the combined size of the left partitions of A1 and A2 equals $k$. Now we can compare the last elements of the left partitions against the first elements of the right partitions:

- If last element of the left partition of A2 is greater than the first element of the right partition of A1, then we have selected too many elements of A2. Therefore, we decrease the size of the left partition of A2 and increase the size of the left partition of A1.
- If last element of the left partition of A1 is greater than the first element of the right partition of A2, then we have selected too many elements of A1. Therefore, we decrease the size of the left partition of A1 and increase the size of the left partition of A2.

We keep doing this until the last elements of the left partitions of A1 and A2 are both less than the first elements of the right partitions of A1 and A2. This means that the values contained in the left partitions of A1 and A2 are all less than all of the values in the right partitions of A1 and A2. To get the $k$-th smallest element, we simply take the largest last value of the left partitions of A1 and A2.

In order to solve this problem efficiently, we are going to use a modified binary search to more quickly find the value of $i$ which satisfies the objective inequalities.

## Justification of Correctness
This algorithm only works because A1 and A2 are sorted. Since A1 and A2 are sorted, there exists some partitioning of A1 and A2 such that $|A1_L|+|A2_R|=k$ and all of the values in $A1_L | A2_L$ are less than or equal all of the values in $A1_R|A2_R$. Since the arrays are sorted, we only need to check the values on the boundary to see if we've found the correct number of elements to put into the left partitions of A1 and A2.

## Runtime Analysis
This algorithm performs a binary search over the range $max \space \{0,k-m\}$ to $min\space\{k, n\}$. In the worst case, we will perform $O(log \space k)$ comparisons, which occurs when $k<n$ and $k<m$. If $k>n$ or $k>m$, then we require $O(min\{log \space m, log \space n\})$ comparisons.
