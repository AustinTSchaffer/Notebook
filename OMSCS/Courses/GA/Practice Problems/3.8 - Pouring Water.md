## 3.8a - Model as a Graph Problem
We can model this problem as a directed state transition graph. For each given state of the 3 beakers, we can define a single vertex in G. The state of the system can be modeled as a 3-tuple of integers, with sum 11. The tuple's indices are defined as follows.

1. The amount of water in beaker 1, capacity 7.
2. The amount of water in beaker 2, capacity 4.
3. The amount of water in beaker 3, capacity 10.

(We could also encode the state as a single integer through clever multiplication and/or bit-shifting, but that's unnecessary obfuscation for the purpose of meeting the interface requirements of the course's graph library.)

From each given state, we can determine all states that can be reached directly from that state by performing every possible move from that state and seeing the resulting state. For all states that differ from the initial state, insert a new vertex into G (if it doesn't already exist in G), and then draw a directed edge from the initial state to that new state. For each state, there are 6 possible state transitions. Using the initial state of (7,4,0) as an example:

- Pour 1 to 2: (7, 4, 0)
- **Pour 1 to 3: (0, 4, 7)**
- Pour 2 to 1: (7, 4, 0)
- **Pour 2 to 3: (7, 0, 4)**
- Pour 3 to 1: (7, 4, 0)
- Pour 3 to 2: (7, 4, 0)

$G$ must be a directed graph, because there do exist state transitions that cannot be traversed in the opposite direction. For example, (2, 2, 7) can reach (0, 4, 7) by pouring beaker 1 into beaker 2, but you can't easily reach (2, 2, 7) directly from (0, 4, 7).

## 3.8b Algorithm
If you can start from the initial state and reach a state which matches either $(2, *, *)$ or $(*, 2, *)$, then that's the answer. After building the state diagram, just run DFS if you don't care about the optimal path, and BFS if you do.
