# 8.1 - TSP optimization versus search
![[Pasted image 20260323214508.png]]

If TSP can be solved in polynomial time, that means we have an $O((n+m)^p)$ algorithm for finding a tour of length $\le b$ within $G,W$. We can use this algorithm to solve TSP-OPT in polynomial time by performing a binary search over the budget parameter $b$, until we find the the optimal budget $\hat{b}$. Considering  this optimal budget $\hat{b}$

- $TSP(G,W,\hat{b})=T$ where $\sum_{e \in T}w_e=\hat{b}$
- $TSP(G,W,\hat{b}-1)=NO$

To find $\hat{b}$, we need some initial guess as to the optimal budget. We can define some upper-bound $B$ for the optimal budget by taking the sum of all edge weights in $G$. ($B=\sum_{e \in E}w_e$). We then take $b_1=B/2$, and run $TSP(G,W,b_1)=S$. 

- If $S=NO$, then
	- we know that $\hat{b}$ must be in range $[B/2,B]$
	- We can set $b_2=(3/4)B$
- Otherwise
	- we know that $\hat{b}$ must be in range $[0,B/2]$
	- We can set $b_2=(1/4)B$

Continuing in this fashion outlines a binary search over the range $(0, B)$. We continue until until we find the crossover condition outlined above, which occurs at the optimal budget $\hat{b}$. The tour returned from $TSP(G,W,\hat{b})$ is the same as the tour returned from $TSP\_OPT(G,W)$, since $\hat{b}$ represents the minimum length for a tour in $G,W$.

TSP-OPT will thus require $O(log(B))$ iterations of TSP, resulting in an overall runtime of $O((n+m)^p log(B))$. We assert that this is polynomial, because $B$ is bounded by the size of the graph.

Notes from TA solution
- **Don't bother** trying to quantify the polynomial runtime of TSP in big-O notation.
- "The input size of **TSP-OPT** must be of length $O(log(B))$, since $B$ was the sum of all the \[weights in $W$\]. Therefore, this reductions is polynomial in the input size to TSP-OPT."
- **Don't forget a signoff**: "If TSP can be solved in polynomial time, then so can TSP-OPT."
