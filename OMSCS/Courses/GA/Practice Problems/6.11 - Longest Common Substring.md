# 6.11 - Longest Common Substring
![[6.11 - Longest Common Subsequence.png]]

Longest Common Subsequence is solved in the lecture notes [[01.1 - Dynamic Programming 1]]. That document is a mess, so we'll resolve that problem here for clarity. We will also be solving the Longest Common Substring problem.

## Longest Common Subsequence
### Subproblem Definition
For $i$ and $j$, where $0 \le i \le n$ and $0 \le j \le n$
let $L(i,j)=$ the length of LCS in $X_{1..i}$ ($\{x_1,...,x_i\}$) and $Y_{1..j}$ ($\{y_1,...,y_j\}$)

### Recurrence Relation
Base Cases
- $L(i,0)=0$
- $L(0,j)=0$

For $1 \le i \le n$ and $1 \le j \le m$

$$
\begin{equation}
  L(i, j) =
    \begin{cases}
      max \space \{L(i-1,j), \space L(i, j-1)\} & \text{if } x_i \ne y_j \\
      1 + L(i-1, j-1) & \text{if } x_i = y_j \\
    \end{cases}       
\end{equation}
$$

- Number of subproblems: $O(nm)$
- Time to fill table: $O(nm)$
- Output extraction: $L(n, m)$
- Output extraction time complexity: $O(1)$

## Longest Common Substring
LCStr is similar to LCSeq, except the matching indices must be contiguous in both $X$ and $Y$.

Given strings:
- X = QQASDFQQASDQQ
- Y = QQQQASDFQQASQQ

"ASDF" is clearly the longest common substring, but how do we do this in $O(nm)$ time?

### Subproblem Attempt 1
L(i,j) = The length of the longest common substring in X_{1..i} and Y_{1..j}? This is how LCSeq is defined. The issue is that it doesn't indicate where the LCStr starts nor stops.

### Subproblem Attempt 2
For 1 <= i <= n and 1 <= j <= m
L(i,j) = The length of the longest common substring in X_{1..i} and Y_{1..j} which includes x_i and y_j.

### Recurrence Relation
Base Cases
- L(0,0) = 0
- L(i,0) = 0 for 1 <= i <= n
- L(0,j) = 0 for 1 <= j <= m

Recursive Cases
For 1 <= i <= n and 1 <= j <= m
- If (x_i =/= y_j) then L(i,j) = 0
- If (x_i = y_j) then L(i,j) = 1 + L(i-1, j-1)

In math code:

$$ \text{For } 1 \le i \le n \text{ and } 1 \le j \le m$$
$$
\begin{equation}
  L(i, j) =
    \begin{cases}
      0 & \text{if } x_i \ne y_j \\
      1 + L(i-1, j-1) & \text{if } x_i = y_j  \\
    \end{cases}
\end{equation}
$$

### Analysis
- Number of Subproblems: O(nm)
- Time to fill the table: O(nm)
- Output Extraction: max{L(\*,\*)}
- Output Extraction Runtime: O(nm)

You can make the output extraction run in O(1) time if you keep track of a max along the way. That is difficult to do in the problem's mathematical notation, and simply moves the processing
- **Option 1:** A single $O(nm)$ operation at the end.
- **Option 2:** A $O(1)$ time complexity operation which is performed $nm$ times.

### Recurrence Relation (Suboptimal Definition)
Originally, the recurrence relation was defined as follows. The parts that differed are shown in bold.

For 1 <= i <= n and 1 <= j <= m
- If (x_i =/= y_j) then L(i,j) = 0
- If (x_i = y_j)
	- **if (i > 1) and (j > 1)** and **(x_{i-1} = y_{j-1})** then
		- L(i,j) = 1 + L(i-1, j-1)
	- **otherwise**
		- **L(i,j) = 1**

- **(x_{i-1} = y_{j-1})**. This part is not needed. If `x_{i-1} != y_{j-1}`, then `L(i-1, j-1) = 0`. If  `x_{i-1} = y_{j-1}`, then `x_i = y_j` simply extends the existing "streak".
- **if (i > 1) and (j > 1)** This part is not needed, because we padded L with zeroes to prevent out of bounds errors.

These don't make the RR "wrong", just overwritten, and needlessly accounting for cases which will never happen. Using this recurrence relation might allow you to slim out the base-cases. In the context of this course, it's better to rely on the base cases for the DP section of the course rather than handle them at runtime.
