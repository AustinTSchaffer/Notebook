# 4.21 - Currency Exchange
![[Pasted image 20260217213238.png]]

Restating this problem for those who are viewing this without support for Obsidian's style of linking images on Markdown.

- Set of currencies: $C=[c_1,c_2,...,c_n]$
- Set of exchange rates: $$R=[[r_{1,2},r_{1,3},...,r_{1,n}], [r_{2,1},r_{2,3},...,r_{2,n}],..., [r_{n,1},r_{n,2},...,r_{n,n-1}]]$$
- **Question 1:** Find optimal strategy for converting $k$ units of currency from $c_i$ to $c_j$ such that you end up with the most amount of currency $c_j$.
- **Question 2:** Are there any cycles in the graph where you start with $1$ unit of $c_a$ and end up with $>1$ units of $c_a$?

## Step 1: Reduce the problem to a graph problem

The first question for a problem of this type is figuring out how to convert the input to a graph. Given the definition of the problem, there's only a guarantee that you can convert $k_1$ units of currency from $c_i$ to $k_2$ units of $c_j$ and then immediately back to $k_3$ units of $c_i$, with a guaranteed loss ($k_3 < k_1$). However, there are no guarantees that you can convert $c_i$ into any $c_j \in C$. There is also no guarantee that the graph is fully-connected, meaning there may be islands where currencies can exchange amongst themselves, but not with the rest of the network. 

**Question 2** leads me to believe that there's some method of building the graph such that edge weights are the "cost" of converting from one currency to a different currency. However, the value of a given currency is only relative to the value of that of a different currency. What is the meta-currency that is "lost" when exchanging between 2 currencies?

The issue with this problem is the **multiplicative** nature of exchange rates. Given a path through the list of of currencies $P=[1, 3, 5, ..., n]$, the resulting units of $c_n$ that you get is equal to the product of the exchange rates between each pair of currencies.

In most graph problems, edge weights are **additive**.

Is there a way to re-encode these multiplicative exchanges as additive? Apparently you can with logarithms. [[00.3 - Exponents and Logarithms]]

### Logarithms
$log_{c}(ab)=log_{c}(a)+log_{c}(b)$

In order to convert this multiplication maximization problem into a summation minimization problem, we can apply the formula $r_{i,j}'=-log_2r_{i,j}$, for every exchange rate $r_{i,j}$.

- The logarithm enables us to re-encode a series of multiplications as a series of additions.
- Multiplying by $-1$ allows us to reframe the maximization problem as a minimization problem.

For a given path through a given subset of currencies $C_{1..4}$ the effective exchange rate is given by $\widehat{r_{1,4}}=r_{1,2}r_{2,3}r_{3,4}$. This value can be projected into logarithmic space, allowing summation-minimizing graph algorithms to operate on it.

- $\widehat{r_{1,4}}'=-log_2(\widehat{r_{1,4}})$
- $\widehat{r_{1,4}}'=-(log_2(r_{1,2} r_{2,3} r_{3,4}))$
- $\widehat{r_{1,4}}'=-(log_2r_{1,2}+log_2r_{2,3}+log_2r_{3,4})$

If needed, we can convert the cost of a given path $\widehat{r_{1,4}}'$ from logarithmic space back to linear space by reversing the conversion.

$$\widehat{r_{1,4}}=\left(\frac{1}{2}\right)^{\widehat{r_{1,4}}'}$$

### Example

Let's imagine the following R-table. Each row represents $i$ and each column represents $j$. Each cell represents $r_{i,j}$, the units of $c_j$ that you get for exchanging a single unit of $c_i$.

| i \ j | 1    | 2   | 3         | 4      |
| ----- | ---- | --- | --------- | ------ |
| **1** | -    | 0.4 | 0.9       | 10     |
| **2** | 1.9  | -   | -         | 0.3    |
| **3** | 0.9  | -   | -         | $10^3$ |
| **4** | 0.05 | 2.5 | $10^{-6}$ | -      |

We want to find the maximum number of units of $c_4$ that can be obtained from exchanging a single unit of $c_1$ through this network.

- $c_1 \rightarrow c_4$
	- $r_{1,4}=10$
- $c_1 \rightarrow c_2 \rightarrow c_4$
	- $r_{1,2}r_{2,4}=(0.4)(0.3)=0.12$
- $c_1 \rightarrow c_3 \rightarrow c_4$
	- $r_{1,3}r_{3,4}=(0.9)(10^3)=900$

The best path is $c_1 \rightarrow c_3 \rightarrow c_4$, which yields a new conversion factor: $r_{1,4}'=900$. However from here, what's the best method for converting $c_4$ into $c_1$?

- $c_4 \rightarrow c_1$
	- $r_{4,1}=0.05$
- $c_4 \rightarrow c_2 \rightarrow c_1$
	- $r_{4,2}r_{2,1}=(2.5)(1.9)=4.75$
- ...

We can stop here. This contrived example shows $r'_{1,4}=900$ and $r'_{4,1}=4.75$. $r'_{1,4}r'_{4,1} \gt 1$, therefore we have an infinite cycle. The best way to test this approach on a graph would be to scrape the current IRL currency trading prices in order to build a network.
