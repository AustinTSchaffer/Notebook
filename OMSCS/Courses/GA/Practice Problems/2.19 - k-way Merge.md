## Strategy A
![[Pasted image 20260207133055.png]]

Strategy A involves using this $merge$ function $k-1$ times to merge all of the values from the $k$ arrays. The runtime of this function for each iteration of $merge$ is shown below.

- $i=1:n+n$
- $i=2:2n+n$
- $i=3:3n+n$
- ...
- $i=(k-1):(k-1)n+n$

$$T(k, n)=\sum_{i=1}^{k-1}(i+1)n$$

On the last few iterations of this summation loop, the values produced are $kn+(k-1)n+(k-2)n+...$ Therefore the runtime of this algorithm is effectively $O(k^2n)$. Also, the resulting array has to be allocated $k-1$ times, also resulting in $O(k^2n)$ space complexity.

## Algorithm Attempt
We package all of the arrays into one 2D array, referred to as $X$, where $|X|=k$ and $|X[i]|=n:1 \le i \le k$. We apply the same $merge$ basic algorithm, except with argmax, and using an array of length $k$ to keep track of the head of each sub-array. This algorithm also has $O(k^2n)$ time complexity, but only $O(kn)$ space complexity.

The drawback of this algorithm is that it presumes $k$ will be small relative to $n$. If $k$ is large compared to $n$, the algorithm will spend a lot of time finding the minimum of $k$ elements at each step.

## Better D&C Algorithm
The reference solution involves merging each array pairwise, before combining combined pairs. For simplicity, presume that the number of arrays to merge is a power of 2.

- At each level in the recursion stack, we need to perform an $O(kn)$ operation.
	- At the first level, we need perform $O(k/2)$ merges. Each merge requires $O(2n)$ time, and results in an array of size $2n$. $k/2*2n=kn$
	- At the second level, we need to perform $O(k/4)$ merges. Each merge results in an array of size $4n$. Each merge requires $O(4n)$ time, and results in an array of size $4n$. $k/4*4n=kn$
	- At the $i$-th level, we need to perform $O(k/2^i)$ merges. Each merge results in an array of size $2^{i}n$. Each merge requires $O(2^{i}n)$ time. $k/2^{i} * 2^{i}n=kn$
- There are $O(log_2 \space k)$ levels in the recursion stack. Each level divides the number of merges by 2. After $log_2 k$ levels, there's only one remaining merge.

This results in an overall $O(kn \space log \space k)$ runtime, and $O(kn \space log \space k)$ space complexity.
