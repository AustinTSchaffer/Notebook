# 2.20 - Sorting in O(n+M) Time
![[Pasted image 20260207165505.png]]

This is an application of the "counting sort" algorithm. In this algorithm:

1. Find the minimum and maximum of $x$. The difference between these quantities is referred to as $M$. This step takes $O(n)$ time.
2. Initialize an array $C$, where $|C|=M$, with all values set to 0. The time complexity of this step is either $O(1)$ or $O(M)$.
3. Iterate $i$ over the indices of $x$, incrementing $C$ at index $x_i-min\{x[\cdot]\}$. This step takes $O(n)$ time.
4. Initialize an array $x'$ of length $n$. The time complexity of this step is either $O(1)$ or $O(M)$.
5. Reconstruct $x$ from $C$, by iterating over $C$ and filling $x'$. This step takes $O(n+M)$ time.

This algorithm is linear time. The $\Omega(n \space log \space n)$ doesn't apply to this algorithm, because it's a special case sorting algorithm which depends on $x$ being integers and having a low range between the largest and smallest values.
