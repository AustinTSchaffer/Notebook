# 2.17 - A_i = i
![[Pasted image 20260207125545.png]]

Target runtime is $O(log \space n)$, so we need to split the subproblem into partitions $b$, but process fewer than $b$ of those partitions. Presumably there's a binary-search equivalent. The array is sorted, and the values are distinct. This problem feels similar to [[2.99 - Modified Binary Search]].

## Algorithm
Look at the element that's in the middle of $A$. We refer to this value as the pivot.
- If the value of the pivot is higher than its index, then we recurse on all of the elements that are less than the pivot.
- If the value of the pivot is lower than its index, then we recurse on all of the elements that are higher than the pivot.

## Justification
We start the search at $A[n/2]$. There are 3 possible outcomes.
- If $A[n/2] = n/2$, then we have found our answer. Yes, there does exist at least one index in $A$ whose value matches its index.
- If $A[n/2] < n/2$, given that $A$ contains sorted/distinct values, then we know that none of the values in $A[1, ..., n/2]$ match their index. There may still exist an element in $A[(n/2)+1, ..., n]$ whose value matches its index. 
- If $A[n/2] > n/2$, given that $A$ contains sorted/distinct values, then we know that none of the values in $A[n/2, ..., n]$ match their index. There may still exist an element in $A[1, ..., (n/2)-1]$ whose value matches its index.

## Runtime
This is a simple adaptation of a binary search algorithm. The only modification to the algorithm is that we check each value against its index, instead of checking each value against some static search value.

This modification does not change the runtime characteristics of a binary search, so therefore the algorithm runs in $O(log \space n)$ time.
